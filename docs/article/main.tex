\begin{abstract}
Linear probes on the activations of generative models often serve as evidence that these models represent the 3D structure of a scene.
We examine this evidence for one simple property, the direction of the light, in the text-to-image diffusion transformer SANA-1.6B.
A first study with controlled Blender renders reported that a Ridge probe on transformer activations predicts the light azimuth with a mean absolute error (MAE) of $14\degr$, also on an object shape that the probe did not see in training.
We audit this pipeline and find four problems.
First, the same probe on raw $64\times64$ pixels gives the same error ($14.1\degr$ against $14.0\degr$).
Second, the noise injection called a library function before its schedule was ready; for $t=200$ the transformer received $-24.5\,x_0 + 25.5\,\epsilon$ instead of $0.8\,x_0 + 0.2\,\epsilon$.
Third, the label described the lamp position around the scene centre, which differs from the light direction at the object by $35\degr$ on average.
Fourth, a large floor highlight under the lamp gives a cue that does not depend on the object.
Probes on image regions show where the information is: the floor alone, without the object, predicts the label on cubes with an MAE of $9.4\degr$, better than the full image ($14.3\degr$), while the object alone fails on cubes ($44.3\degr$).
We release an exact re-implementation of the render geometry, a corrected extraction pipeline, unit tests, and a fix for the library pitfall, which affects four schedulers.
We close with a checklist for probe studies of generative models and with the plan for causal tests.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Text-to-image diffusion models make images with plausible light, shadows and perspective.
Do they build an internal model of the 3D scene, or do they only reproduce 2D image statistics?
Probe studies try to answer this question with linear models on frozen activations: if a linear probe can read depth, surface normals or the light direction, the activations encode this property \citep{alain2016probes,chen2023beyond,elbanani2024probing,zhan2024protocol}.

A probe result alone is weak evidence.
A probe can read a property that the input already shows in a simple form, and a flexible probe can learn the task itself \citep{hewitt2019control,belinkov2022probing}.
Thus a claim about the knowledge of a model needs controls: a baseline on the input, a baseline on a model without training \citep{adebayo2018sanity}, labels that describe the physical quantity, and data without shortcut cues \citep{geirhos2019texture}.

This paper examines one probe study in detail.
The study used SANA-1.6B \citep{xie2025sana}, a linear diffusion transformer with a flow-matching objective, and renders from a modified CLEVR generator \citep{johnson2017clevr} with one object and one key lamp.
It reported that a Ridge probe on block~10 at timestep $t=200$ predicts the lamp azimuth with an MAE of $14.0\degr$ on cubes, a shape that the probe did not see in training (Table~\ref{tab:original}).
The study concluded that SANA encodes the light direction as a physical property of the scene.

We re-examine every step of this pipeline: the render geometry, the labels, the noise injection, the probe fit and the figures.
Our contributions are:
\begin{enumerate}
    \item An audit that finds four problems that each can explain the result without 3D knowledge (Section~\ref{sec:audit}).
    \item Control probes on pixels and on image regions, which show that the floor of the image carries the information (Section~\ref{sec:controls}).
    \item Tools: an exact model of the render geometry (to $0.56$~px), a corrected extraction pipeline with unit tests, and a fix with tests for a pitfall in the noise schedulers of a popular diffusion library (Section~\ref{sec:pipeline}).
    \item A checklist for probe studies of generative models, and a pre-registered plan for causal tests with concept erasure and steering (Section~\ref{sec:discussion}).
\end{enumerate}

\section{Related work}
\label{sec:related}

\paragraph{Probes and their controls.}
Linear probes test whether a layer encodes a property in a linearly decodable form \citep{alain2016probes}.
\citet{hewitt2019control} showed that a probe can be accurate because it learns the task, and proposed control tasks and selectivity.
\citet{belinkov2022probing} reviews these and other limits.
Concept vectors such as TCAV \citep{kim2018tcav} and regression concept vectors \citep{graziani2018rcv} use the same linear directions as explanations.
Erasure methods remove a linear concept from the activations and test whether the model needs it \citep{ravfogel2020inlp,elazar2021amnesic,belrose2023leace}.
Randomized models give a baseline for explanations \citep{adebayo2018sanity}.

\paragraph{3D and physical knowledge in generative models.}
\citet{chen2023beyond} found linear representations of depth and of the salient object in a latent diffusion model, and changed the output with interventions on these representations.
\citet{zhan2024protocol} probed Stable Diffusion features for scene geometry, support relations, shadows, occlusion and depth.
\citet{elbanani2024probing} compared the 3D awareness of visual foundation models with depth and normal probes.
\citet{du2023generative} and \citet{bhattad2023stylegan} extracted normals, depth, albedo and shading from generative models with small adapters.
In contrast, \citet{sarkar2024shadows} found that generated images often have inconsistent shadows and perspective.

\paragraph{Light in diffusion models.}
Several methods control the light of generated images \citep{zhang2025iclight,zeng2024dilightnet,kocsis2024lightit}, and a diffusion model can estimate the scene light from an image \citep{phongthawee2024light}.
These results show that diffusion models can use light information, but not where or how the model represents it.

\section{The original study}
\label{sec:original}

\paragraph{Data.}
A modified CLEVR script renders one purple rubber object (sphere, cylinder or cube) in each scene with Blender 2.78c and Cycles at $512\times512$ px.
The key lamp has a random azimuth $\phi\sim\mathcal{U}(0\degr,360\degr)$ and elevation $\theta\sim\mathcal{U}(30\degr,75\degr)$ on a sphere of radius~5 around the scene centre.
There are 1000 images for each shape.
The probe trains on 1600 spheres and cylinders; 200 images are for validation and 200 for the test.
The 1000 cubes form the set \texttt{test\_cubes}.

\paragraph{Activations.}
Each image goes through the DC-AE encoder of SANA-1.6B ($1024\times1024$ input, $32\times32\times32$ latent).
Noise for timestep $t\in\{200,500,800\}$ is added, and forward hooks record the output of transformer blocks 4, 10 and 18 (1024 tokens with 2240 channels) for the empty prompt.

\paragraph{Probe.}
A $4\times4$ average pool gives $8\times8\times2240$ features.
Incremental PCA (256 components) and a Ridge regression ($\alpha=1$) predict $[\sin\phi,\cos\phi,\theta]$.
The azimuth is $\hat\phi=\operatorname{atan2}(\hat s,\hat c)$.

\section{Audit of the pipeline}
\label{sec:audit}

\subsection{An exact model of the render geometry}
\label{sec:geometry}

To check labels and figures, we need the exact camera of each image.
The CLEVR camera has a track-to constraint on the scene centre, a 35~mm lens on a 32~mm sensor, and a random jitter in $[-0.5,0.5]$ on each axis that the scene files do not store.
We wrote the projection of Blender in NumPy and fitted the jitter of each image to the object position in the scene file (pixel position and depth).
The fit reproduces the pixel position of all 3000 objects with a maximum error of $0.56$~px, and the fitted jitter is uniform in $[-0.5,0.5]$.
A new render of a dataset scene with these values equals the dataset image (mean absolute difference $0.14/255$, object-mask IoU $0.98$).

The azimuth turns counter-clockwise in the world and in the image: $0\degr$ means light from the front right, $90\degr$ from the back right, $180\degr$ from the back left and $270\degr$ from the front left (Figure~\ref{fig:conventions}).
The original report described the opposite direction.

\subsection{The label is the lamp position, not the light at the object}

The lamp turns around the scene centre, but the object stands up to $2.8$ units from the centre.
The light direction at the object, $\mathrm{dir}(L-p)$ for lamp $L$ and object centre $p$, differs from the label by $35.0\degr$ in azimuth (mean; median $27.2\degr$) and by $16.2\degr$ in elevation (mean absolute value).
At the object, the light elevation spans $8\degr$ to $89\degr$, not $30\degr$ to $75\degr$.
The original probe follows the label: its azimuth MAE on cubes is $14.0\degr$ for the label and $35.5\degr$ for the light at the object.
So the probe reads the position of the lamp in the scene, and not the light that falls on the object.

\subsection{Scene lights and a shortcut cue}

The key lamp is an area lamp that always faces the scene centre.
It makes a bright spot on the floor between the lamp and the centre, and the position of this spot follows the label (Figure~\ref{fig:conventions}).
The spot is larger and brighter than the cast shadow of the object, and it does not depend on the object shape.
The CLEVR base scene also contains a sun lamp (strength $0.45$, from azimuth $334.9\degr$ and elevation $62.7\degr$) that the modified script did not switch off.
With the white world light, it gives $19\%$ of the floor brightness.
Its shadow falls behind the object as the camera sees it, so the effect is a constant front light.

\subsection{A pitfall in the noise schedule}
\label{sec:noise}

The original code noised the latent with \texttt{scheduler.add\_noise} of the SANA scheduler (\texttt{DPMSolverMultistepScheduler} with flow sigmas) before any call to \texttt{set\_timesteps}.
After construction, this scheduler stores variance-preserving sigmas in ascending order of the training step, while its timesteps are in descending order.
The function finds the index of $t$ in the descending list and reads the sigma of step $999-t$.
With flow sigmas it then computes $x_t=(1-\sigma)x_0+\sigma\epsilon$ with this value of $\sigma$.
Table~\ref{tab:noise} shows the result: for $t=200$ the transformer receives an input with $35$ times the expected norm and an inverted signal, while its timestep embedding says $\sigma=0.2$.
The stored activations agree with this: in block 4 the mean token norm is about $11{,}100$ at $t=200$ and $720$ at $t=800$.
The same order problem affects the variance-preserving case of four schedulers of the library. We reported the problem to the maintainers of the library, with a fix and tests (the link is withheld for anonymity).

\subsection{Figures and probe fit}

The figures of the original study drew the shadow direction with the default Blender camera instead of the CLEVR camera and with an orthographic projection.
The mean direction error is $5.2\degr$, and $16\%$ of the scenes have an error above $10\degr$.
Because the arrows had a fixed length from the object centre, about $18\%$ of them ended outside the image and the plot library did not draw them.
Renders without the object confirm our exact arrows: for scenes with long shadows, the mean angle between our arrow and the measured shadow is $4.7\degr$ ($7.6\degr$ for the original arrows).
Finally, the Ridge $\alpha$ had no effect (the same MAE for $\alpha$ from $10^{-3}$ to $10^{3}$), because the PCA scores were not scaled, and the final configuration was selected with test data.

\section{Controls on the existing data}
\label{sec:controls}

All controls use the original splits.
The probe is the same recipe (PCA with 256 components, then Ridge), with standard scores after the PCA and $\alpha$ from a log grid selected on the validation split only.
Intervals are 95\% bootstrap intervals over the test images.

\paragraph{Pixels.}
Table~\ref{tab:original} shows that a probe on raw pixels is as good as the probe on SANA activations, on spheres and cylinders ($11.5\degr$ against $13.0\degr$) and on cubes ($14.1\degr$ against $14.0\degr$).
The input image already contains the label in a linearly decodable form.

\paragraph{Image regions.}
To find the region that carries the information, we fit the probe on four variants of each image (Table~\ref{tab:cues}): the full image; the image with the object replaced by the floor colour (the cast shadow and the floor highlight stay); a crop of the object alone on a grey background; and only the position of the brightest floor region (two numbers).
The floor carries the label.
Without the object, the probe is better than with it ($9.4\degr$ against $14.3\degr$ on cubes), because the object only adds shape-specific variance.
The position of the floor highlight alone, two numbers, gives $12.2\degr$ on the test split and $17.6\degr$ on cubes.
The object alone predicts the light at the object well on known shapes ($7.7\degr$), which is the expected physical cue, but this cue does not transfer to cubes ($21.5\degr$) and it does not predict the lamp label ($44.3\degr$ on cubes).
Thus the transfer to cubes that the original study reported is a property of the floor cues, which do not depend on the object shape.
Figure~\ref{fig:cues} shows the variants and the errors.

\section{A corrected pipeline}
\label{sec:pipeline}

The corrected extraction (package \texttt{dd3d}) uses the flow rule $x_t=(1-t/1000)\,x_0+(t/1000)\,\epsilon$, a fixed noise seed for each image, and the attention mask of the empty prompt.
All five timesteps $t\in\{100,200,400,600,800\}$ of one image go through the transformer as one batch.
The features of all 20 blocks are average-pooled to a $4\times4$ grid, and blocks 4, 10 and 18 also to the $8\times8$ grid of the original study (float16).

\paragraph{Agreement with the original pipeline.}
With the original noise rule, our extraction gives a mean token norm of $11{,}147$ in block~4 at $t=200$; the stored original activations have about $11{,}100$.
With the flow rule, the norm is $718$.
Thus our pipeline agrees with the original one, except for the noise.

\paragraph{Numeric precision.}
The runs use a T4 GPU, which has no bfloat16 arithmetic.
On the same 12 images, float16 and float32 give the same features (relative difference $0.1\%$; cosine of the centered features $0.9999$), and float16 is four times faster.
The original noise rule gives inputs with 35 times the expected norm, which overflow in float16 in block 18; this control therefore runs in float32.

\paragraph{Controls.}
Each data set has the same probe on: the input pixels ($64\times64$); the DC-AE latent; SANA-1.6B with random weights \citep{adebayo2018sanity}; and, for generality, the UNets of Stable Diffusion 1.5 and SDXL with the noise rule of their own schedules.

\section{Clean data: one directional light and a controlled position}
\label{sec:clean}

\paragraph{Data set v2.}
We rendered 3000 new images with the same camera and object sizes, but with these changes: the key lamp is a sun lamp (only a direction, so the label is exact at every point of the scene); the extra sun lamp of the base scene is off; a flat floor replaces the curved backdrop, whose back wall blocks a sun lamp from behind; there is no camera jitter; and the object stands at the scene centre.
The elevation is $\mathcal{U}(30\degr,75\degr)$, as in the original data, and the splits follow the same rules.

\paragraph{A centred object makes the pixel control almost perfect.}
On v2, the pixel probe has an azimuth MAE of $2.5\degr$ on spheres and cylinders and $13.7\degr$ on cubes.
With the object always at the same place, the shadow always falls in the same part of the image, and a linear read-out of the pixels needs no 3D knowledge.
The floor brightness also shows the elevation: the floor alone gives an elevation MAE of $1.7\degr$ on cubes, because a low sun lights the floor less.
Thus the elevation is not a useful target for a claim about 3D knowledge, and we use the azimuth.
The same pixel probe on 300 images with the object at random positions has an azimuth MAE of $69.0\degr$, close to chance ($90\degr$).
Figure~\ref{fig:maps} shows where the pixel probe reads the azimuth: on v1, the weight spreads over the floor, where the highlight moves; on v2, it lies around the object and its shadow.

\paragraph{Data set v2r: a random position.}
The decisive test needs data in which the shadow position depends on the object position.
Data set v2r has the same lights, sizes and rotations as v2, image for image; only the position changes.
The position is uniform on the part of $[-3,3]^2$ where the largest object is fully in the image; this region depends only on the camera, so the position does not correlate with the light ($|r|<0.01$).
The tip of the shadow is in the image for $99\%$ of the scenes.

\paragraph{A random position removes the linear shortcut.}
On v2r, the pixel probe has an azimuth MAE of $25.1\degr$ on spheres and cylinders and $25.8\degr$ on cubes, against $2.5\degr$ and $13.7\degr$ on v2.
A pixel probe fitted on v2 and tested on v2r has $71.2\degr$ and $70.4\degr$, close to chance.
The information is still in the image: a crop of the object alone, which removes the position, gives $4.4\degr$ on spheres and cylinders.
Thus the light direction is present, but a linear read-out of the pixels cannot find it at an arbitrary place in the image.
A model with a representation of the light that does not depend on the position must do better than $25\degr$ on v2r.
The floor brightness still gives the elevation ($2\degr$).

\paragraph{Weak cues remain.}
Without the cast shadow (the first variant, object at the centre), the floor alone still predicts the azimuth ($4.6\degr$; $10.2\degr$ on cubes).
The cue is the light that the purple object reflects onto the floor on its lit side.
This cue is physically correct, but it is one more 2D cue that a probe can read.

\paragraph{Cue variants.}
Two more variants have the same scenes as v2r: in the first, the object casts no shadow (only its shading is left); in the second, the camera does not see the object, but its shadow stays.
A pair of images thus differs in one cue only.

\section{Probes on the clean data}
\label{sec:rq1}

\paragraph{Protocol.}
For each model we fit the probe on every block and on the timesteps $t\in\{100,200,400,600,800\}$.
The features of a block are the token means on a grid of $1\times1$, $2\times2$, $4\times4$ or $8\times8$ cells; the $1\times1$ grid is the mean of all tokens and has no information about the position.
The validation split selects the block, the timestep and the grid of each model (criterion: the sum of the azimuth and elevation MAE).
The pixel baseline is the same probe on the RGB image at $8\times8$, $16\times16$, $32\times32$ or $64\times64$ pixels, and the validation split also selects this resolution.
A coarse grid is often the stronger linear baseline, because it averages the position of the shadow.
A control task with shuffled train and validation labels gives an MAE of $83\degr$ to $93\degr$ for every source, so the probes do not fit noise \citep{hewitt2019control}.

\paragraph{With a random position, diffusion features are much better than the input.}
On v2r the SANA probe (block 5, $t=100$, $2\times2$ grid) has an azimuth MAE of $5.4\degr$ on spheres and cylinders and $7.6\degr$ on cubes.
The DC-AE latent gives $18.8\degr$ and $19.0\degr$, and $64\times64$ pixels give $25.1\degr$ and $25.8\degr$.
SD~1.5 ($7.5\degr$, $11.1\degr$) and SDXL ($5.9\degr$, $7.3\degr$) show the same effect, so it is not specific to one model.
The SANA transformer with random weights is better than the latent at a low noise level ($11.9\degr$, $15.9\degr$), because random nonlinear features of the latent already help a linear probe.
The trained model reduces this error by about half.

\paragraph{The representation does not depend on the position.}
The mean of all tokens (the $1\times1$ grid) still gives $5.9\degr$ on spheres and cylinders of v2r ($13.2\degr$ on cubes).
A stronger test fits the probe on v2, where the object is always at the centre, and applies it to v2r.
The pixel probe fails ($71.2\degr$ and $70.4\degr$, near chance).
The SANA probe on the mean of all tokens (block 5, $t=100$) gives $9.0\degr$ and $17.6\degr$; SD~1.5 gives $10.6\degr$ and $22.0\degr$.
With the $8\times8$ grid, which keeps the position, the transfer is weaker ($38.4\degr$ and $40.9\degr$).
Thus the model has a direction code that is the same at every place in the image, and the cell features add a position-dependent part.

\paragraph{Both cues are readable.}
Without the cast shadow (v2rns), the SANA probe gives $6.9\degr$ and $9.9\degr$; the best pixel grid gives $24.6\degr$ and $23.3\degr$.
With only the shadow (v2rso), SANA gives $5.9\degr$ and $7.9\degr$, against $24.6\degr$ and $16.9\degr$ for the pixels.
So the model encodes the light from the shading of the object and from the cast shadow, each one alone.

\section{Does the model use the direction?}
\label{sec:causal}

A probe shows that a property is readable, not that the model uses it \citep{elazar2021amnesic,belinkov2022probing}.
We test use with three interventions during generation.
All three start from a render of v2.
We encode the render, add flow noise up to $\sigma_0=0.7$, and integrate the flow back to $\sigma=0$ in 20 Euler steps, $x_{\sigma'}=x_\sigma+(\sigma'-\sigma)\,v_\theta(x_\sigma,\sigma)$ \citep{meng2022sdedit}.
Without an intervention, this gives a close copy of the render (the base output).
A forward hook on one transformer block changes its output at every step.
A pixel probe, fitted on the v2 renders, measures the azimuth of each output, and we report the signed rotation against the base output of the same image and noise.

\paragraph{Shift along a direction.}
The probe of block $b$ is linear in the cell features: $\hat{\mathbf y}=W h+c$.
We add a vector $\delta$ to all tokens of each grid cell, which changes the cell mean by exactly $\delta$.
We use two directions.
The probe direction is the shortest change that turns the probe output $(\hat s,\hat c)$ by $90\degr$: $\delta=W^\top(WW^\top)^{-1}(R_{90}\hat{\mathbf y}-\hat{\mathbf y})$, applied as it is and scaled to the mean token norm of the block.
A probe weight vector can contain directions that only cancel noise in the data, so it is not the best candidate for a change that the model uses \citep{haufe2014interpretation,marks2024geometry}.
The second direction is the activation pattern: a least-squares regression of the features on $(\sin\phi,\cos\phi)$ over the train split gives a matrix $B$, and $\delta=(\mathbf y(\phi+90\degr)-\mathbf y(\phi))B$ is the mean feature change between images whose light differs by $90\degr$.
We apply it with factors 1 and 3.
Each direction has a control: a random vector with the same norm in each cell.
This is a form of activation steering \citep{turner2023activation,chen2023beyond}.

\paragraph{Erasure.}
The LEACE eraser \citep{belrose2023leace} of $(\sin\phi,\cos\phi)$, fitted on the cell features of the train split, removes all linear information about the azimuth from every token of the block.
If the model uses this information in later blocks, the output light must change or become less consistent with the input light.

\paragraph{Patch test.}
The shift and the erasure depend on a linear direction.
The patch test does not \citep{meng2022locating,zhang2024patching,basu2024localizing}.
For 48 test scenes of v2 we rendered a second image of the same scene with the light azimuth $+90\degr$ (set v2rot).
Both images get the same noise.
The source pass (v2rot) records the output of a block at every step.
In the target pass (v2), the tokens of one region get the recorded source values at every step.
The regions come from the scene geometry: all tokens, the object, the cast shadow of the source light, the cast shadow of the target light, and the rest of the floor.
If the patched tokens carry the light direction that the model uses, the shadow of the output turns towards the source light.
We report the rotation as a fraction of the $90\degr$ offset.
In a transformer without skip connections, a patch of all tokens at all steps makes the output equal to the source output up to the difference of the two inputs, so this condition is a positive control.

\paragraph{Results of the shift and the erasure.}
Table~\ref{tab:causal} and Figure~\ref{fig:causal} give the results for 60 test images of v2 and three blocks.
The probes come from the $8\times8$ features at $t=400$ (test MAE $4.4\degr$ to $4.6\degr$).
The base output keeps the light of the render (azimuth MAE $7.6\degr$ against the label).
\begin{itemize}
    \item The pattern direction turns the light of the output. With the natural size ($\times1$), the measured azimuth turns by $+60\degr$ (block~10), $+65\degr$ (block~4) and $+62\degr$ (block~18) towards the target of $+90\degr$, and $73\%$ to $82\%$ of the images end within $45\degr$ of the target.
    This change has a mean cell norm of only $2\%$ of the mean token norm, and the mean pixel change is $4$ grey levels.
    With $\times3$ the rotation is about $+120\degr$, so the effect grows with the dose; at this size the images show artefacts.
    \item A random vector with the same norm in each cell does nothing ($-1.5\degr$ to $-0.2\degr$).
    \item The shortest change along the probe weights, which moves the probe output exactly to $+90\degr$, turns the output by only $+23\degr$ to $+41\degr$. The same direction with the size of the token norm destroys the image in blocks 4 and 10 (mean pixel change above 130 grey levels).
    \item The LEACE eraser in one block has no effect on the output light (rotation $-0.2\degr$ to $+0.2\degr$, MAE against the label $7.7\degr$ to $7.9\degr$).
\end{itemize}
Thus the model uses the direction of the activation pattern: a small change along it moves the shadow, and a random change of the same size does not.
The probe weights are a worse handle, as \citet{haufe2014interpretation} predict for a regression with correlated noise.
The erasure result does not show that the information is unused: the noisy input at $\sigma_0=0.7$ still shows the shadow, and later blocks can read the light again from it.

\section{Discussion}
\label{sec:discussion}

\paragraph{What the original result shows.}
The original probe reads the lamp position, and pixels give the same accuracy.
The floor highlight and the shadow are visible in 2D and do not depend on the object shape, which explains the transfer to cubes.
Therefore, the result does not show that SANA represents the light direction as a 3D property.
It also does not show the opposite: the corrected extraction and the controls in Section~\ref{sec:pipeline} must decide whether SANA adds information that the input does not make linearly available.

\paragraph{A checklist for probe studies of generative models.}
\begin{enumerate}
    \item Compare every probe with the same probe on the input pixels and on the latent of the autoencoder.
    \item Compare with the same architecture with random weights.
    \item Check the noise that the model receives: fit $x_t=a\,x_0+b\,\epsilon$ and compare with the schedule of the model.
    \item Define the label at the place of the effect (here, the light at the object), and store all scene parameters (camera, all lamps).
    \item Remove or randomize shortcut cues (floor highlights, constant extra lights) before a claim about 3D knowledge, and test cue-conflict images.
    \item Vary the object position. With a fixed position, a linear probe reads the image location of the shadow, and the pixel control is almost perfect.
    \item Select hyperparameters on validation data only, and report intervals.
    \item Test causal use, for example with concept erasure \citep{belrose2023leace} and with steering along the probe direction \citep{chen2023beyond}.
    \item Check figures against the true geometry.
\end{enumerate}


\section{Limitations}
One model, one property and synthetic scenes limit the scope of this study.
The controls in Section~\ref{sec:controls} use the original dataset, which has the shortcut cues that we describe.
The results of the corrected extraction need GPU time and are not part of this draft.

\section{Conclusion}
A probe that reads a scene property from a generative model is a starting point, not evidence of 3D knowledge.
In the case that we studied, input baselines, exact labels and a check of the noise schedule change the conclusion.
We release the tools so that other studies can run the same checks.

\paragraph{Reproducibility.}
The code, the configurations, the audit tables and the unit tests are in the supplementary material.
The geometry model reproduces the scene files to $0.56$~px, and every number in this draft comes from a script in the repository.

The shadow of the object centre $p$ on the floor is $L+\tfrac{L_z}{L_z-p_z}(p-L)$.
